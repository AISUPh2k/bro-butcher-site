# Сайт мясной лавки БРО

Статический интернет-магазин: без сервера, базы и CMS. Заказ собирается в корзине (хранится в браузере покупателя)
и уходит сообщением в WhatsApp на +7 925 007-18-00 — так же, как заказывают сейчас.

## Структура

```
data/products.json   каталог: 175 товаров (импортирован со старого сайта myaso-sobakam-bro.ru 17.10.2026)
data/site.json       контакты, условия доставки, акции, ID Яндекс.Метрики
static/              стили, скрипты, шрифты, фото товаров
build.py             сборка: data + static -> dist/
dist/                готовый сайт (генерируется, вручную не править)
```

## Сборка и просмотр

```sh
python3 build.py                      # нужен только Python 3.8+, без зависимостей
xdg-open dist/index.html              # открыть локально
python3 -m http.server -d dist 8000   # или через локальный сервер: http://localhost:8000
```

## Как править товары

Каждый товар в `data/products.json`:

| поле | что это |
|---|---|
| `slug` | адрес страницы `p/<slug>.html`, не менять у существующих |
| `name` | название |
| `cat` | основная категория: mix, premium, beef, lamb, poultry, rabbit, offal, farsh, treats, econom, opt |
| `tags` | все категории, где товар виден в фильтре |
| `options` | фасовки и цены: `[["0,5 кг", 185], ["0,7 кг", 245], ["1 кг", 320]]`; последняя выбрана по умолчанию |
| `in_stock` | `false` — «Нет в наличии», кнопка покупки выключена |
| `composition` | состав списком: `["Говядина — 50%", "Сердце — 20%"]` |
| `notes` | абзацы описания |
| `kbju` | `null` или `{"b": 16, "z": 12, "u": 0, "kcal": 176}` на 100 г — появится на карточке и странице товара |
| `veg` | миксы с овощами (бейдж) |
| `img` | файл в `static/img/products/`, 800×600 JPG; пусто — аккуратная заглушка |
| `popular` | место в «Покупают чаще всего» (меньше — выше), `null` — не в хитах |

Условия доставки, телефон, акция «Приведи друга» — в `data/site.json`; после правки снова `python3 build.py`.

## Фото товаров

```sh
python3 tools/images.py фото.jpg slug   # обрежет поля, приведёт к 800×600, сделает WebP 400/800
python3 tools/images.py                 # пересчитать WebP для всех фото (нужен Pillow)
```

## Проверка перед публикацией

```sh
python3 build.py && python3 tools/check.py   # битые ссылки, картинки, пустые title/description
```

## Публикация

Залить содержимое `dist/` на любой статический хостинг (GitHub Pages, Netlify, обычный хостинг с FTP).
Для GitHub Pages файл `.nojekyll` уже создаётся. Канонический адрес задаётся в `site.json → base_url`.

При переезде с OpenCart на тот же домен старые адреса товаров (`/govyadina/...`) поменяются на `/p/<slug>.html`.
`build.py` сам создаёт по старым адресам страницы-переадресации (203 шт.: все товары, разделы,
«О нас», «Оплата и доставка», FAQ) с canonical на новую страницу. Если хостинг позволяет — лучше
дополнительно настроить настоящие 301-редиректы; старый адрес каждого товара лежит в поле `old_url`.

## Админка (цены, фасовки, описание, фото, объявления)

```sh
python3 tools/admin_server.py --password   # один раз: задать пароль (хранится хэш в admin.secret.json)
python3 tools/admin_server.py              # панель: http://127.0.0.1:8100/admin/   сайт: http://127.0.0.1:8100/
```

- «Сохранить» (или Ctrl+S) пишет `data/*.json` и сразу пересобирает `dist/`. Прошлая версия файла — в `data/backups/` (последние 60).
  Если сборка упала, изменения откатываются сами.
- Фото: браузер уменьшает до 1600 px, сервер (Pillow) режет до 800×600 + WebP. HEIC с iPhone не принимается — подсказка в панели.
- «Скрыть с сайта» убирает товар (старый адрес ведёт в его раздел каталога); удаления нет специально.
- «Хит» = `popular` 1–10. Фасовки с весом «200 г»/«0,5 кг» сортируются сами.
- Объявления = `site.json → slides` (слайдер на главной), можно выключить или задать дату снятия.
- `admin.secret.json` и `data/backups/` не публиковать (в `dist/` они не попадают).

## Приём заказов на почту (локально — через сервер админки)

- `tools/orders.py`: проверка заявки, пересчёт цен по `products.json`, номер заказа, журнал `orders/<год>/<№>.json`, письмо-накладная (HTML на 1 лист A4 + текст).
- Настройка: `cp orders.config.example.json orders.config.json` и вписать SMTP (пароль приложения ящика). `"mode": "outbox"` — письма не отправляются, а кладутся в `orders/outbox/`.
- Корзина шлёт заказ на `/api/order`, только если сайт собран с `BRO_ORDER_API` (так делает admin_server). Обычный `python3 build.py` — заказ уходит в WhatsApp, как раньше.
- Не ушло письмо → клиенту показывается номер и кнопка «Отправить через WhatsApp», заказ остаётся в журнале.
- `orders/` и `orders.config.json` — персональные данные и пароль, не публиковать.
